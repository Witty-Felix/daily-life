# 功过格

**Triage:** `ready-for-agent`  
**Created:** 2026-09-09  
**Feature status:** Specified; implementation not started

## Problem Statement

当前应用只有“课间”记录，缺少一个独立、低干扰的日常自省入口。用户希望参考《了凡四训》中“逐日登记、善则记数、恶则退除”的功过格思想，记录自己当天做过的善行与发生的过失，并通过简单、固定的分值观察当天状态。

这个功能不能把自省变成道德审判、人与人之间的排名或对现实福报的承诺。页面需要在保留“功过格”传统气质的同时，明确区分古籍启发与现代产品规则：每件善行记 `+1`，每件过失记 `-2` 是本产品自定义的固定规则，不宣称是《了凡四训》正文规定的完整分值表。

## Solution

在现有应用中增加一个独立的“功过格”一级页面，并提供配套的“功过簿”历史页面和设置面板。

“功过格”首页聚焦当天的核心动作：

- 查看今日善行数量、过失数量和今日净分；
- 记录一件善行；
- 记录一件过失；
- 查看今天已经记录的行为；
- 进入设置。

每条记录只代表一件具体行为。善行固定计 `+1`，过失固定计 `-2`。记录只保存所属自然日，不保存具体时分秒；用户从当天页面新增的记录归入当天，第一版不提供补记过去日期的入口，也不允许选择未来日期。

通过主导航进入“功过簿”后，用户可以使用日历查看历史日期，并查看选中日期的善行、过失、数量和净分。当天记录可以直接编辑或删除；过了当天的记录保留原始内容，只能在原记录详情中追加可追溯的修正信息。修正信息不作为主时间线中的独立行为显示，但修正后的有效结果应参与相关统计。

视觉上采用用户提供的图片所表达的风格方向：宣纸米色、水墨黑、朱砂红、书法标题和少量印章/笔刷装饰。图片本身只是视觉参考，不直接作为页面背景或功能内容；正文、表单、数字和交互控件仍使用清晰易读的现代排版。

## User Stories

1. 作为用户，我希望从主导航独立进入“功过格”，以便不必先开始一次课间就能进行日常自省。
2. 作为用户，我希望进入功过格时看到今天的善行数量，以便快速了解今天记录过多少件善行。
3. 作为用户，我希望进入功过格时看到今天的过失数量，以便快速了解今天记录过多少件需要反省的行为。
4. 作为用户，我希望看到今日净分，以便快速获得当天记录的整体概览。
5. 作为用户，我希望在首页直接点击“记善行”，以便用最少步骤记录一件具体善行。
6. 作为用户，我希望在首页直接点击“记过失”，以便用最少步骤记录一件具体过失。
7. 作为用户，我希望新增善行和新增过失使用同一种记录面板，以便学习一次交互后即可完成两类记录。
8. 作为用户，我希望打开记录面板时记录类型已经根据入口预选，以便减少重复操作。
9. 作为用户，我希望填写一件具体行为的描述，以便记录真实发生的事情，而不是只留下一个抽象分数。
10. 作为用户，我希望行为描述是必填项，以便避免产生没有内容的空记录。
11. 作为用户，我希望可以选填“反思或修复行动”，以便在记录过失时写下下一步准备如何改进。
12. 作为用户，我希望善行永远按 `+1` 计算，以便规则稳定、简单且不会因为主观调整而改变。
13. 作为用户，我希望过失永远按 `-2` 计算，以便过失在净分中具有固定且明确的影响。
14. 作为用户，我希望一条记录只对应一件行为，以便记录粒度清晰，避免用一句笼统描述一次性获得多分。
15. 作为用户，我希望记录默认归入当天，以便不需要手动填写日期就能完成快速记录。
16. 作为用户，我希望第一版不提供补记过去日期，以便保持“当天记录当天行为”的简单边界。
17. 作为用户，我希望第一版不允许选择未来日期，以便避免历史统计被未来记录污染。
18. 作为用户，我希望记录只保存日期而不保存具体时分秒，以便功过格关注“哪一天”而不是记录行为的精确时间。
19. 作为用户，我希望保存后立即回到功过格首页，以便马上确认今日统计和今日记录已经更新。
20. 作为用户，我希望保存后能在今日记录列表中看到刚刚新增的行为，以便确认内容和分类没有记错。
21. 作为用户，我希望首页显示今天的记录列表，以便在同一页面回看善行和过失，而不必先进入历史页面。
22. 作为用户，我希望善行和过失出现在同一条今日时间线中，以便看到当天完整的行为记录。
23. 作为用户，我希望善行和过失在列表中有清晰但克制的视觉区别，以便快速识别类型而不产生羞辱感。
24. 作为用户，我希望当天记录可以直接编辑，以便及时纠正文字、类型或反思内容上的错误。
25. 作为用户，我希望当天记录可以直接删除，以便处理误操作或不应保存的记录。
26. 作为用户，我希望把当天一条记录从善行改为过失时系统自动重新计算分数，以便统计始终反映当前有效记录。
27. 作为用户，我希望把当天一条记录从过失改为善行时系统自动重新计算分数，以便不需要手动抵消旧分数。
28. 作为用户，我希望过了当天后原始记录仍然保留，以便历史记录具有可追溯性。
29. 作为用户，我希望过往记录不能被直接删除，以便避免通过删除历史来掩盖已经记录过的行为。
30. 作为用户，我希望过往记录可以在原记录详情中追加修正，以便纠正历史记录但保留原始变化过程。
31. 作为用户，我希望修正历史只在原记录详情中展示，以便主时间线仍然只呈现行为本身，而不是充满系统修正项。
32. 作为用户，我希望过往记录修正后相关日期的统计能够重新计算，以便历史数字与当前有效记录一致。
33. 作为用户，我希望净分可以低于零，以便负向记录不会被系统强行隐藏或归零。
34. 作为用户，我希望负分状态只得到中性提示，而不是被标记为失败或坏人，以便页面支持反思而不是自我惩罚。
35. 作为用户，我希望页面不要求我通过新增善行来抵消过失，以便避免把修复责任简化为刷分。
36. 作为用户，我希望首页没有记录时看到清晰的空状态引导，以便知道下一步可以记录善行或过失。
37. 作为用户，我希望功过格首页不展示复杂趋势图、连续天数或目标进度，以便页面保持专注和低干扰。
38. 作为用户，我希望从主导航进入“功过簿”，以便查看今天以外的历史记录。
39. 作为用户，我希望“功过簿”提供按月份浏览的日历，以便从日期维度回看自己的记录。
40. 作为用户，我希望日历能区分有善行、有过失以及两者都有的日期，以便不打开详情也能获得基本线索。
41. 作为用户，我希望点击日历中的某一天后看到该日的善行和过失列表，以便查看具体行为而不只看到汇总数字。
42. 作为用户，我希望在功过簿中看到选中日期的善行数量、过失数量和净分，以便把行为明细和数字概览联系起来。
43. 作为用户，我希望历史页保留清晰的日期上下文，以便知道当前查看的是哪一天。
44. 作为用户，我希望可以从功过簿返回功过格首页，以便继续快速记录当天行为。
45. 作为用户，我希望功过格提供设置按钮，以便管理数据和查看规则说明。
46. 作为用户，我希望设置以面板或抽屉形式打开，以便查看设置后仍能快速返回功过格首页。
47. 作为用户，我希望在设置中看到善行 `+1`、过失 `-2` 的规则说明，以便理解净分如何产生。
48. 作为用户，我希望不能在设置中修改分值，以便所有记录遵循同一套规则。
49. 作为用户，我希望在设置中看到功过格的史料来源说明，以便知道页面受到《了凡四训》相关思想启发。
50. 作为用户，我希望来源说明明确指出 `+1 / -2` 是现代产品自定义规则，以便不把页面规则误认为古籍原始分值表。
51. 作为用户，我希望来源说明默认收起，以便史料内容不会阻塞主要记录流程。
52. 作为用户，我希望设置中有本地数据提示，以便知道记录只保存在当前浏览器，不会自动同步到其他设备。
53. 作为用户，我希望可以导出功过格数据为 JSON，以便完整备份并在未来恢复。
54. 作为用户，我希望可以导出功过格数据为 CSV，以便用表格软件查看和整理记录。
55. 作为用户，我希望清空功过格时看到明确的二次确认，以便避免误删长期记录。
56. 作为用户，我希望清空功过格只影响功过格数据，不影响课间记录或课间设置，以便两个功能保持独立。
57. 作为用户，我希望刷新页面后功过格记录仍然存在，以便本地应用不会因为刷新而丢失数据。
58. 作为用户，我希望在已有进行中课间时进入功过格，以便功过格不会被课间状态阻塞。
59. 作为用户，我希望进入或使用功过格不会结束课间、修改抽取结果或增加课间记录，以便两个功能互不干扰。
60. 作为用户，我希望在手机上也能轻松完成记录，以便功过格适合日常快速使用。
61. 作为用户，我希望页面使用宣纸、水墨、朱砂和书法标题等视觉语言，以便感受到传统功过格的文化气质。
62. 作为用户，我希望装饰不会遮挡文字或影响按钮点击，以便传统视觉不会牺牲可用性。
63. 作为用户，我希望正文和表单使用易读的现代字体，以便长文本、日期和统计数字清晰可读。
64. 作为用户，我希望负分和过失使用克制的颜色表达，以便页面提醒我反思而不是制造警告或羞耻。
65. 作为用户，我希望页面尊重系统的减少动态效果偏好，以便在需要时降低装饰动画和视觉干扰。

## Implementation Decisions

- 功过格是现有应用中的独立一级页面，与课间首页、进行中的课间、课间历史和贪吃蛇页面并列；它不属于课间状态机，也不创建或结束课间。
- 主导航新增功过格入口；功过格内部的历史页面正式命名为“功过簿”。
- 功过格首页只突出今日善行数量、今日过失数量、今日净分、今日记录列表、记善行、记过失和设置入口，不在首页放长期趋势、目标、连续记录或复杂图表。
- 新增记录使用一个共享的记录面板。入口决定记录类型，行为描述必填，反思或修复行动选填。
- 记录类型使用“善行”和“过失”，不使用“坏事”作为正式页面术语。
- 每条记录只代表一件具体行为，不提供数量字段；第一版不通过一条记录批量生成多件行为。
- 善行固定计 `+1`，过失固定计 `-2`；分值不可在设置中修改。
- 净分由当前有效记录的善行分与过失分相加得到，允许为负数；净分仅用于行为趋势观察，不代表用户整体道德价值，也不用于人与人比较。
- 功过记录只保存所属自然日，不保存具体时分秒。新增记录默认归入浏览器本地自然日；第一版不允许补记过去日期，也不允许选择未来日期。
- 当天记录允许直接编辑和删除。编辑记录类型、行为描述或反思内容后，首页和功过簿中的相关统计立即以当前记录为准。
- 过往记录保留原始记录，不提供直接删除；修正通过原记录详情完成，并保留原值、新值和修正信息的可追溯关系。修正不在主时间线中作为新的普通行为展示，但修正后的有效结果参与统计。
- 功过簿提供月份日历和日期详情。日期标记至少能表达“有善行”“有过失”“两者都有”；选中日期后展示该日统计和记录列表。
- 设置以不离开功过格首页的面板或抽屉呈现，包含规则说明、史料来源、本地数据提示、JSON 导出、CSV 导出和清空功过格记录。
- 清空操作只清除功过格自己的记录和相关状态，不清除课间记录、进行中的课间或课间动画设置；清空前必须确认。
- 功过格数据沿用现有无登录、本地浏览器保存的产品边界，不新增账号、云端同步或跨设备同步。
- JSON 导出保留恢复所需的完整记录信息，包括记录标识、日期、类型、行为描述、反思或修复内容以及修正关系；CSV 导出提供适合阅读和表格处理的扁平记录数据。
- 视觉实现采用低对比度宣纸色背景、墨色正文、朱砂色重点操作、局部水墨笔触和书法气质标题。用户提供的图片仅作为风格参考，不直接承担文本内容、交互或响应式布局。
- 善行入口使用朱砂色作为主要强调，过失入口使用墨色或暖灰色；负分使用克制的深朱砂或墨红，不使用刺眼的错误警告红。
- 页面装饰必须服从内容可读性、键盘操作、触控目标尺寸、颜色对比度和小屏幕布局；在系统减少动态效果时不依赖动画传达信息。
- 史料说明使用“受《了凡四训》功过格启发”的表述，并明确说明：古籍正文提供的是每日登记、善加过减的思想来源；本页面的 `+1 / -2` 为现代产品规则；页面不提供命运、财富、寿命、婚育或其他现实结果承诺。
- 不将后世流传的复杂功过条目和等级表直接作为第一版输入选项、评分表或现代通用道德标准。

### Primary test seam

- 最高层测试入口是渲染后的应用行为：通过现有应用支持的可替换本地存储和可控当前日期，验证导航、记录、统计、编辑、删除、修正、历史、设置和课间共存行为。这样优先测试用户实际看到和操作到的结果，而不是组件内部实现细节。
- 在需要隔离纯规则时，补充测试记录评分、按日期聚合、修正后有效结果和导出转换等无副作用领域逻辑；这些测试只验证输入到输出的外部契约。
- 不以 CSS 类名、React 组件层级、具体存储键名或内部状态变量作为测试目标。

## Testing Decisions

- 好的测试应从用户可观察行为出发：点击入口、填写表单、保存记录、看到统计变化、切换日期、刷新恢复、打开设置、导出数据和清空确认都应通过可观察结果验证。
- 首要验收使用现有的应用级组件测试模式，注入内存存储和固定日期，避免真实系统时间及真实浏览器历史数据造成不稳定。
- 应增加或扩展领域层测试，覆盖：善行计 `+1`、过失计 `-2`、净分允许为负、空记录统计、跨日期聚合、同日编辑、过往修正以及修正后统计重新计算。
- 应增加或扩展本地存储层测试，覆盖：功过格记录持久化、刷新后恢复、非法或缺失数据的安全处理、只清空功过格数据、导出数据的一致性。
- 应增加真实浏览器端到端测试，覆盖：主导航进入功过格、移动端布局、记录善行和过失、今日列表更新、功过簿日历切换、设置面板、导出下载、清空确认以及已有进行中课间时的独立使用。
- 应验证当天与过往记录的边界：当天记录可直接编辑和删除，过往记录只能从详情追加修正，修正不生成主时间线中的独立普通行为。
- 应验证日期只包含自然日语义，不向用户显示具体时分秒，也不允许新增未来日期。
- 应验证负分提示为中性文案，不出现“失败”“坏人”“惩罚”或自动刷分建议。
- 应验证视觉验收至少包括宣纸背景、水墨/朱砂风格、标题层级、按钮可读性、移动端不溢出和减少动态效果下的信息完整性。
- 完成实现后，继续使用仓库已有的类型检查、单元测试、生产构建和浏览器验收命令作为回归门槛；功过格新增测试不得破坏课间现有行为。

## Acceptance Criteria

- 用户可以从主导航打开独立的功过格首页。
- 功过格首页显示今日善行数量、今日过失数量和今日净分。
- 用户可以通过两个明确入口分别新增善行和过失。
- 新增记录必须有行为描述；反思或修复行动可以为空。
- 新增记录只保存当天日期，不保存具体时分秒，不支持未来日期或第一版补记历史日期。
- 善行固定 `+1`，过失固定 `-2`，净分可以低于零。
- 首页显示今日记录列表，并在保存、编辑、删除后更新。
- 当天记录可直接编辑或删除；过往记录保留原始内容，只能在原记录详情中追加修正。
- 修正信息只在原记录详情中展示，不作为主时间线中的独立普通行为；有效统计能够反映修正后的结果。
- 功过簿提供日历、日期标记和选中日期的记录列表与统计。
- 设置面板包含固定规则、史料说明、本地数据提示、JSON 导出、CSV 导出和清空功过格记录。
- 清空功过格不会影响课间记录、进行中的课间或课间动画设置，并且清空前需要确认。
- 刷新页面后功过格数据能够恢复；功过格与课间功能可以并行使用且互不修改对方状态。
- 页面符合宣纸、水墨、朱砂和书法标题的视觉方向，同时保持现代文字可读性、响应式布局、键盘可操作性和触控可用性。
- 页面不包含自定义分值、传统等级分值表、排行榜、命运兑换、结果型愿望、提醒、连续打卡、云端同步或社交比较。

## Out of Scope

- 将功过格作为课间抽取出来的放松方式。
- 把功过格记录绑定到一次课间的开始、结束或完成状态。
- 传统“准百功、准五十功、准一功”等完整功过条目和复杂分级评分。
- 用户自定义善行或过失分值、按严重程度动态计分、分数兑换奖励。
- 通过分数预测或承诺财富、功名、寿命、婚育、健康或其他现实结果。
- 道德等级、排行榜、社交分享或人与人之间的分数比较。
- 每日提醒、浏览器通知、连续记录天数和强制完成目标。
- 第一版行为目标或“发愿”目标管理。
- 用户账号、云端同步、跨设备同步和服务端数据存储。
- 第一版补记过去日期、选择未来日期、输入具体时分秒。
- 复杂标签系统、用户自定义快捷选项和完整分类管理。
- 以“做一件善行”自动抵消过失，或用积分替代道歉、补偿、求助等实际修复行动。
- 将用户提供的图片直接作为页面背景、交互控件或唯一标题内容。

## Further Notes

- “功过簿”是历史查看页面的正式名称；“功过格”是记录首页和整个功能的名称。
- 页面正式用语为“善行”和“过失”。“坏事”可以用于需求讨论，但不作为界面正式文案。
- 负分只表示当前统计范围内的记录结果，不代表用户的整体价值或人格评价。
- 史料说明应保持简短、可展开，并将“古籍启发”“后世流传”和“现代产品规则”分层说明，避免把不同文本和时代的规则混为一谈。
