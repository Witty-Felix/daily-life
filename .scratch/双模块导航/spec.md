# 双模块导航

Status: ready-for-agent
Date: 2026-09-10

## Problem Statement

用户希望产品页面只呈现两个清晰、等权的一级模块：“课间松一松”和“功过格”。当前顶部导航同时展示首页、进行中、功过格、功过簿、最近 7 天和设置，混合了核心模块、页面、临时状态与辅助操作，使信息层级显得繁杂，也让“功过格”与“课间松一松”的关系不够清楚。

用户需要在两个一级模块之间自由切换，同时保留正在进行的课间；历史、设置和功过簿仍需可访问，但不应继续占据一级目录。产品还需要在刷新或重新打开时恢复用户最后选择的一级模块，并保护功过格表单中尚未保存的输入。

## Solution

页面顶部改为仅包含两个横向、等权的一级模块入口：“☼ 课间松一松”和“功过格”。“课间松一松”保留品牌识别作用，但不能在尺寸、交互面积或选中表现上把“功过格”降为附属功能。

课间首页、进行中课间、最近 7 天、课间设置和贪吃蛇归属于“课间松一松”；今日功过记录、功过簿、功过格设置、导出和清空归属于“功过格”。设置入口移至相应模块首页内容区域的右上角。二级页面提供模块内返回路径，并让父级一级目录保持选中。

一级模块偏好保存在当前浏览器中。首次使用默认进入“课间松一松”；此后刷新、关闭后重开或新标签页打开时恢复最后选择的一级模块，但不恢复功过簿、最近 7 天、所选日期、滚动位置或设置面板等临时状态。

存在进行中的课间时，用户仍可进入功过格，课间不会结束或丢失。“课间松一松”入口显示低干扰、可访问的进行中标记。如果功过格表单已有未保存输入，切换模块前要求用户确认是否丢弃。

本次只重构共享导航、模块状态和相应响应式布局，保留两个模块已有且不同的内容视觉语言，也不改变任何课间或功过格业务规则。

## User Stories

1. 作为用户，我希望页面顶部只有“课间松一松”和“功过格”两个一级模块，以便一眼理解产品的主要功能。
2. 作为用户，我希望两个一级模块在视觉和交互上等权，以便不会误以为功过格只是课间功能的附属页面。
3. 作为用户，我希望“课间松一松”继续保留太阳标志，以便延续现有品牌识别。
4. 作为用户，我希望页面不再单独显示“首页”一级入口，以免首页和课间模块概念重复。
5. 作为用户，我希望“进行中”不再是一级目录，以便把它理解为课间模块的一种状态，而不是独立功能。
6. 作为用户，我希望“最近 7 天”不再是一级目录，以便它明确归属于课间记录。
7. 作为用户，我希望“功过簿”不再是一级目录，以便它明确归属于功过格。
8. 作为用户，我希望“设置”不再是第三个一级目录，以便顶部结构始终只有两个核心模块。
9. 作为首次使用者，我希望打开产品时直接进入课间松一松，以便无需先通过额外的模块选择页。
10. 作为回访用户，我希望产品恢复我最后选择的一级模块，以便继续上次的使用方向。
11. 作为回访用户，我希望只恢复一级模块而不是上次的二级页面，以免回到过时的历史日期、滚动位置或临时面板。
12. 作为用户，我希望点击“课间松一松”时，有进行中的课间就直接返回该课间，以便快速继续当前活动。
13. 作为用户，我希望点击“课间松一松”时，没有进行中的课间就进入课间空闲首页，以便开始新的课间。
14. 作为用户，我希望点击“功过格”时始终进入今日功过首页，以便优先记录当前行为。
15. 作为正在课间中的用户，我希望可以切换到功过格，以便记录善行或过失而不必结束课间。
16. 作为正在课间中的用户，我希望切换模块不会更改抽取结果、完成状态、贪吃蛇局数或其他课间数据，以便安全返回。
17. 作为位于功过格的用户，我希望通过课间入口旁的小圆点知道仍有进行中的课间，以便需要时返回。
18. 作为位于功过格的用户，我希望不被持续横幅或弹窗提醒课间状态，以便专注记录功过。
19. 作为使用辅助技术的用户，我希望进行中标记具有明确的文本语义，以便无需依赖颜色或视觉圆点理解状态。
20. 作为用户，我希望当前一级模块有明显选中状态，以便始终知道自己处于哪个模块。
21. 作为色觉差异用户，我希望选中状态不只依靠颜色，以便仍能辨别当前模块。
22. 作为位于最近 7 天页面的用户，我希望“课间松一松”保持选中，以便理解该页面的父级模块。
23. 作为位于功过簿的用户，我希望“功过格”保持选中，以便理解该页面的父级模块。
24. 作为位于最近 7 天页面的用户，我希望有明确的返回按钮，以便回到课间模块入口。
25. 作为位于功过簿的用户，我希望有明确的返回按钮，以便回到功过格今日首页。
26. 作为正在进行贪吃蛇游戏的用户，我希望页面只保留“返回活动”而隐藏一级目录，以便减少误触和游戏中断。
27. 作为课间空闲首页用户，我希望能在内容区域右上角找到“设置”，以便管理课间规则和本地记录。
28. 作为功过格首页用户，我希望能在内容区域右上角找到“设置”，以便导出或管理功过记录。
29. 作为用户，我希望设置按钮明确显示“设置”文字，以便无需猜测图标含义。
30. 作为进行中课间的用户，我希望页面不显示设置入口，以便当前活动保持专注。
31. 作为浏览历史的用户，我希望最近 7 天和功过簿页面不重复显示设置入口，以便页面层级简洁。
32. 作为用户，我希望当前模块只打开自己的设置，以免混淆两套数据和规则。
33. 作为设置面板中的用户，我希望仍能切换一级模块，以便不必先手动关闭面板。
34. 作为设置面板中的用户，我希望切换模块时旧设置自动关闭，以免在新模块中看到错误归属的设置。
35. 作为填写功过记录的用户，我希望已有未保存输入时切换模块会收到确认，以免意外丢失内容。
36. 作为填写功过记录的用户，我希望取消离开后表单和输入保持原样，以便继续编辑。
37. 作为打开空白功过表单的用户，我希望切换模块时不被不必要地拦截，以便快速离开。
38. 作为用户，我希望第一版不自动保存功过草稿，以便产品不增加隐蔽的临时数据和过期规则。
39. 作为用户，我希望清除课间记录只影响课间数据，以便功过格和模块偏好不受影响。
40. 作为用户，我希望清空功过格记录只影响功过格数据，以便课间数据和模块偏好不受影响。
41. 作为用户，我希望模块切换本身不修改或清除任何业务记录，以便可以放心导航。
42. 作为多标签页用户，我希望另一个标签页切换模块时当前页面不自动跳转，以免正在进行的操作被打断。
43. 作为多标签页用户，我希望刷新或新开页面时能读取最新模块偏好，以便后续访问保持一致。
44. 作为移动端用户，我希望顶部仍横向显示两个清楚、近似等宽的模块入口，以便快速切换且无需打开菜单。
45. 作为桌面端用户，我希望两个模块在同一横向导航中清晰排列，以便减少页面顶部的视觉噪声。
46. 作为用户，我希望课间松一松继续保留轻松、现代的内容风格，以便改版不破坏熟悉的使用氛围。
47. 作为用户，我希望功过格继续保留纸张、印章和书法感的内容风格，以便维持其自省语境。
48. 作为用户，我希望本次改版不改变抽取、换一个、完成、结束和贪吃蛇规则，以便原有课间行为保持稳定。
49. 作为用户，我希望本次改版不改变善行、过失、净分、修正、导出和清空规则，以便原有功过记录保持稳定。
50. 作为用户，我希望模块切换不依赖新的网址或浏览器前进后退，以便静态网站继续保持简单可靠。

## Implementation Decisions

- 将“一级模块”与“模块内部页面”建模为两个层级。一级模块只有课间松一松和功过格；首页、进行中、最近 7 天、功过簿和贪吃蛇是相应模块的内部页面或状态。应避免继续使用一个扁平状态集合同时表达模块与子页面，因为它容易产生无效组合和错误的选中状态。
- 顶层共享导航只渲染两个模块入口。课间松一松包含太阳识别标志，但两个入口使用同等级的标签布局、点击区域和选中表达。
- 当前模块的判定基于父级模块，而不是仅匹配模块首页。最近 7 天归属课间松一松，功过簿归属功过格。
- 打开课间松一松采用统一入口规则：存在进行中的课间时进入当前课间，否则进入空闲首页。该规则同时用于顶部入口、跨模块返回和二级页面退出。
- 打开功过格采用统一入口规则：进入今日功过首页，不记忆或恢复此前的功过簿日期。
- 模块切换不归档、不完成、不替换也不清除进行中的课间。现有课间存储继续作为进行中课间的事实来源。
- 存在进行中课间时，课间模块入口显示低干扰状态标记。标记应包含可供辅助技术读取的“进行中”语义，不能只依赖视觉颜色。
- 模块偏好使用独立的本地界面偏好存储，与课间存储及功过格存储隔离。允许值只有课间松一松和功过格；缺失或无效值回退到课间松一松。
- 用户主动选择一级模块时更新模块偏好。二级页面切换、设置开关、记录清除和业务状态变化不修改模块偏好。
- 初始化时先读取模块偏好。偏好为功过格时，即使存在进行中的课间也进入功过格；偏好为课间松一松时再依据是否存在进行中课间选择空闲首页或当前课间。
- 模块偏好通过当前浏览器的持久存储跨刷新、浏览器重开和新标签页生效。已打开的其他标签页不监听偏好变化，也不自动切换画面。
- 不持久化二级页面、功过簿日期、历史页位置、滚动位置、打开的对话框、设置面板或功过表单。
- 设置入口从共享顶层导航移除，改为模块首页内容区域右上角的文字按钮。
- 课间设置只在课间空闲首页显示；功过格设置只在今日功过首页显示。进行中课间、最近 7 天、功过簿和贪吃蛇不显示设置入口。
- 两套设置继续保持独立内容和独立数据作用范围，不新增全局设置中心。
- 设置面板打开时允许使用一级模块入口。模块切换在进入目标模块前关闭当前设置及不需要保留的普通弹窗，避免设置归属错位。
- 功过记录表单需要暴露“是否存在未保存输入”的页面级状态。未保存输入至少包括相对于表单初始值发生变化的行为描述、反思、修正说明或类型选择；仅打开未编辑的空白表单不视为脏状态。
- 从脏的功过表单发起模块切换时，先显示离开确认。取消保持当前模块、表单和输入；确认后丢弃输入、关闭表单并按目标模块入口规则导航。
- 第一版不实现功过草稿自动保存，也不把未保存输入写入业务记录或模块偏好。
- 最近 7 天和功过簿保留明确的模块内返回操作。返回操作不改变一级模块偏好，因为用户仍处于同一模块。
- 贪吃蛇继续作为专注页面隐藏共享顶层导航，只显示返回当前活动的操作。
- 桌面端和移动端都采用顶部横向双模块导航。移动端两个入口近似等宽，并保持足够触控区域，不改为底部栏、下拉菜单或纵向目录。
- 当前模块选中状态至少结合底线、背景、形状、字重或可访问属性中的多种信号，不能只改变文字颜色。
- 共享顶部导航和响应式布局可以调整，但课间松一松与功过格的内容区视觉语言保持独立，不进行全站视觉统一重做。
- 不新增客户端路由依赖，不引入独立模块路径，也不通过浏览器历史记录表达模块切换。
- 不修改课间与功过格领域模型、计分规则、统计口径、数据保留范围或业务存储格式。唯一新增的持久状态是独立的一级模块偏好。

## Testing Decisions

- 主要测试缝使用现有的顶层应用组件行为测试。这是能够同时观察导航、模块内容、设置面板、进行中课间和功过表单的最高现有测试缝，不需要为导航状态新增更低层的单元测试。
- 组件测试只通过用户可见的角色、名称、选中状态、提示文本和页面内容断言行为，不直接断言内部状态变量、具体事件处理函数或私有存储实现。
- 在顶层应用组件测试中覆盖：顶层只显示两个一级模块；父级模块选中状态；课间入口的空闲/进行中分支；功过格始终进入今日首页；设置的可见范围与模块归属；设置打开时切换模块；脏表单离开确认及取消后的输入保留。
- 使用现有可注入的课间存储、功过格存储、时间、随机数和标识生成能力构造确定场景，避免依赖真实时间或随机结果。
- 模块偏好应通过其公开可观察行为测试：首次进入默认课间松一松，重新挂载或刷新后恢复最后一级模块，无效偏好回退，清除任一业务模块数据后偏好保持。
- 真实浏览器端到端测试只覆盖组件环境无法可靠证明的边界：页面刷新后的持久偏好、进行中课间与功过格共存、浏览器本地存储隔离、移动端横向双标签布局和触控可用性。
- 浏览器测试应通过可见 UI 建立状态，只有在准备跨刷新或异常偏好场景时才直接种入本地存储；不得把内部存储对象结构作为主要断言目标。
- 响应式测试至少覆盖现有桌面和手机视口，验证两个入口同时可见、不转为下拉或底部导航、没有横向溢出，并且设置位于模块内容区域而非一级导航行。
- 可访问性断言覆盖：当前模块的 `aria-current` 语义、进行中状态的可读名称、键盘可操作性、设置与离开确认的对话框角色，以及脏表单取消离开后的焦点和内容保留。
- 回归测试继续覆盖现有课间核心流程、一次进行中课间约束、换一个、完成与结束分离、最近 7 天统计、贪吃蛇、功过计分、修正、导出和独立清除，证明本次导航改版未改变业务行为。
- 现有测试先例包括顶层应用组件的课间与功过格交互测试，以及真实浏览器中的核心课间、历史与本地数据、响应式设置和功过格流程。新增测试应沿用这些高层行为风格，而不是针对样式类名或组件拆分方式编写脆弱测试。
- 理想测试缝数量为一个顶层应用行为缝；浏览器端到端缝仅作为持久化与响应式验证的必要补充，不重复覆盖全部业务流程。

## Out of Scope

- 不新增第三个总览首页、双卡片模块选择页或新的总品牌名称。
- 不新增全局设置中心，也不合并课间设置与功过格设置。
- 不新增账号、登录、云同步或服务端状态。
- 不新增模块级 URL、客户端路由库、可分享路径或浏览器前进后退导航。
- 不实现跨标签页实时模块同步或自动跳转。
- 不持久化最近 7 天、功过簿日期、滚动位置、弹窗或其他二级页面状态。
- 不实现功过记录自动草稿保存。
- 不统一重做两个模块的全部视觉设计。
- 不改变课间抽取概率、换一个、完成、结束、归档、记录保留或贪吃蛇规则。
- 不改变善行、过失、净分、修正、导出、清空或功过记录日期规则。
- 不改变课间与功过格现有业务数据格式，除新增独立模块偏好外不做数据迁移。

## Further Notes

- 本规格由已完成的设计访谈、项目领域词汇表和当前应用行为综合生成，不再包含待用户回答的产品问题。
- 当前实现的顶部导航仍混合模块、子页面、状态与设置；实施时应以本规格定义的两层信息架构为准。
- 当前实现已经具备顶层应用组件测试和多组浏览器验收测试，因此不需要为了本功能新增测试基础设施。
